# Check Token Limit

## What it does

Counts each file's size in LLM tokens (`ceil((bytes − CR) / 4)`) and fails when any
file exceeds **5000 tokens (20000 bytes)** — the default, overridable with `--max`.
CR bytes are subtracted so LF and CRLF checkouts measure identically. Large files
are hard for AI coding agents to read, edit, and review — this keeps every
committed file agent-friendly.

The script is bundled, dependency-free plain JavaScript:

```
node <this-skill-dir>/scripts/check-token-limit.mjs <file|directory>... [--exclude <regex>] [--max <tokens>]
```

Resolve `<this-skill-dir>` from this file's location: `scripts/check-token-limit.mjs`
sits next to this SKILL.md.

## When to use

- A commit was blocked by the lefthook "token limit" job — run the script on
  the listed files, split them per the printed instructions, re-add.
- Asked to audit file sizes: scan a directory (`node ...mjs .` for the whole
  repo) and report offenders.
- Before committing a file you suspect is large.

## Behavior

- **Files**: checked directly. Skip rules apply to direct file args too, not
  just scans.
- **Directories**: recursively listed via `git ls-files --cached --others
--exclude-standard`, so `.gitignore`, `.git/info/exclude`, and the global
  git excludes are respected — gitignored build output is never scanned.
- **Always skipped** (not agent-authored):
  - Lockfiles across ecosystems: `bun.lock`, `bun.lockb`, `package-lock.json`,
    `pnpm-lock.yaml`, `yarn.lock`, `Cargo.lock`, `go.sum`, `Gemfile.lock`,
    `poetry.lock`, `uv.lock`, `pdm.lock`, `composer.lock`
  - Codegen conventions: `*.gen.*`, `*.generated.*`, `__generated__/`,
    `migrations/` (any depth — generated by nearly every ORM/framework)
  - Source maps (`*.map`), minified bundles (`*.min.js`/`*.min.css`),
    `CHANGELOG.md`, `tsconfig.tsbuildinfo`
  - Binary assets, including SVG (it is an image; agents must not edit its markup)
  - Vendored agent tooling dirs (`.agents`, `.claude`, `.codex`, `.gemini`,
    `.cursor`, `.opencode`, `.omo`, `.bmad-loop`, `_bmad`, `_bmad-output`)
- **`--exclude <regex>`**: skips repo-specific generated files that do not
  match the conventions above (e.g. `payload-types.ts`), from the hook config
  or audit command. Never edit the script per-repo.
- **`--max <tokens>`**: overrides the default limit for one run. Changing the
  committed default is the user's decision — see below.
- **Cross-platform**: backslash paths (Windows) are normalized to `/`; CR
  bytes are excluded from the count so CRLF and LF checkouts measure the same.
- Missing files are skipped silently.

## Mandatory user confirmation

The script runs unattended, but three actions change policy or committed
structure. The agent MUST ask the user and wait for approval before:

1. **Adding a new `--exclude`** to lefthook.yml, CI config, or any audit
   command. Excludes weaken the limit — show the file that triggered it and
   the proposed regex, then wait.
2. **Splitting an offender that is source code** (anything under `src/**` or
   the repo's equivalent). Restructuring committed code needs consent —
   present the proposed split (which types/helpers move where) first. Docs
   and data/fixture splits are mechanical; proceed directly.
3. **Changing the limit**. Suggest `--max <tokens>` when a file genuinely
   cannot be split, but only pass it after the user gives a value or approves
   yours. Never edit the script's default.

## Exit codes

| Code | Meaning                                                                      |
| ---- | ---------------------------------------------------------------------------- |
| 0    | All files within the limit (or none passed)                                  |
| 1    | At least one file exceeds the limit — offenders + split instructions printed |
| 2    | `git ls-files` failed, invalid `--exclude` regex, or invalid `--max` value   |

## Splitting offenders

The script prints topic-specific instructions on failure:

- **Code**: extract types to `types.ts`, constants to `constants.ts`, helpers
  to their own modules, one React component per file, re-export public API
  from `index.ts`.
- **Docs**: one topic per file, link between them, move long samples to
  `examples/`.
- **Data/fixtures**: trim to minimum or generate at test time.

After splitting, `git add` the new files so they are included in the commit.
